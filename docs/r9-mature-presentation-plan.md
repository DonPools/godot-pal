# R9 成品表现与操作复核计划

> 执行状态（2026-08-20）：R9-0 至 R9-4 的实现、自动门与静态门已完成；共享 HUD、主题、
> 环境构图和操作契约已推广到五张地图与全部顶层 UI。四段 60 FPS 自动动态诊断也已干净通过，
> 但它们不是真人输入证据。四组真实输入录像和 5 人首次玩家盲测仍待执行，R9 尚未达到完成定义。目标帧与视觉规范见
> `docs/baselines/r9/target-frames.md`。
> 待执行的真实录制与盲测步骤见 `docs/baselines/r9/field-test-protocol.md`；该协议不会替代结果。
> 外部执行包已经包含隔离测试 profile、只观察的真实输入 JSONL、结果模板和只读完整性 CLI；这些
> 工具降低采集误差，但仍不构成任何一名真人的通过记录。
> 逐项证据与缺口判定见 `docs/baselines/r9/completion-audit.md`。

## 1. 状态与背景

R8 已经建立可工作的桌面 ARPG 操作、战斗反馈、设备提示、设置与辅助功能基线。2026-08-20
按成熟单机游戏标准重新检查真实 Metal 截图和当前操作契约后，结论是：现有实现属于系统完整、
信息可读的高级原型，但角色姿态、世界层次、UI 一致性、信息取舍和动态手感证据仍不足以支持
“成品表现完成”。

R9 不否定 R8 的规则和架构成果，也不扩充玩法内容。它把现有能力集中到一段可反复比较、录制和
盲测的成品体验中，再把通过验证的表现规范推广到其余场景。

## 2. 目标与非目标

R9 的目标是让第一次接触项目的玩家在不阅读 README 的情况下：

- 从标题页立即理解作品的修仙行旅气质，而不是先看到技术演示说明。
- 在进入地图后自然理解移动、互动、当前目标与可通行方向。
- 在首场战斗中区分普攻、技能、闪避、体力、真气和敌人前摇，并理解动作被拒绝的原因。
- 使用键鼠或手柄打开菜单、调整设置并稳定返回游戏。
- 感受到标题、世界、HUD、对话、菜单、设置和存读档属于同一款游戏。

R9 明确不做：

- 新地图、新境界、新敌人族群、新法器分支或新剧情章节。
- 随机词缀、无限刷怪、装备品质、队友 AI、赛季、天气或通用 Boss 阶段编辑器。
- 改写 BattleSession 固定步规则、GameRun、StoryContext、内容 schema 或地图生成所有权。
- 为美术表现增加 GameSession、GameFlow、全局 EventBus、自定义 SubViewport 或新的长期状态。
- 在黄金体验通过验收前，同时翻修五张地图和全部界面。

## 3. 黄金 90 秒

R9 先只完成一段稳定的验证路径：

```text
标题页首次焦点
  -> 开始游戏与短过渡
  -> 阵灯隘口入口：辨认道路、守灯人和第一目标
  -> 点地移动 / 直移接管 / 靠近互动
  -> 第一批有限敌群：普攻、技能、闪避、真气反馈
  -> 战后与守灯人对话
  -> 打开暂停菜单，进入设置，再返回地图
```

“90 秒”是统一录制、评审和比较的目标长度，不是强迫新玩家速通的规则。截图工具可以通过确定性
状态构造覆盖关键画面，但动态验收必须来自真实输入和正常场景生命周期。

## 4. 成熟度标准

| 层面 | R9 标准 | 不接受的状态 |
|---|---|---|
| 第一印象 | 标题、主角轮廓、世界入口和音乐共同建立作品身份 | 技术副标题、绑定姿势人物、大片空背景主导画面 |
| 世界画面 | 道路、地表、边界、植被、灯光和功能色形成前中后景 | 大块无节奏纯色地面、裸露黑边、均匀撒点 |
| 角色与敌人 | idle/run/attack/cast/hit/death 在固定镜头下都有明确剪影 | A/T pose、动作首帧长期停留、盒状轮廓难以辨认 |
| HUD | 当前最重要的生命、真气、目标和动作优先，教程按情境出现 | 六格文字卡与常驻操作说明共同压缩战场 |
| 界面系统 | 共享字体、暗金/墨绿主题、间距、焦点和设备提示规则 | 每个场景复制独立颜色和 StyleBox，设置页像开发工具 |
| 操作 | 点击、直移、追击、闪避、目标切换和菜单返回响应稳定 | 静默失败、目标黏错、输入残留、非常规默认键无引导 |
| 可访问性 | 减少闪烁后仍保留动作方向、命中和资源信息 | 通过关闭全部反馈换取舒适度 |

## 5. 设计与架构原则

- 继续使用 `640 x 360` 根 Viewport、整数缩放、固定正交 Camera3D 和原生 Control UI。
- 世界主体优先于 HUD；没有即时决策价值的信息不常驻战斗画面。
- 功能色保持稳定：旅人绿表示玩家，阵灯金表示目标/选择，真气蓝表示资源，橙红表示敌意/危险。
- UI 通过共享 Theme Resource 与少量明确的共享 StyleBox/图标资源统一，不增加 UI Manager。
- `.tscn` 继续负责组合和生命周期；原创 GLB、纹理、材质与生成记录继续位于 `assets/original/`。
- SettingsService/InputMap 继续是输入设置真相；GameScene 和 Overlay 的输入所有权边界保持不变。
- R9 可以调整默认绑定与表现反馈，但不能让表现脚本修改战斗结果或存档领域状态。

## 6. 实施阶段

### R9-0：目标帧与表现清单

产出：

- 标题、隘口探索、首战和设置页四张 `640 x 360` 目标帧。
- 字体层级、有限色板、面板透明度、边框、焦点、功能色和最小可读字号规范。
- 当前角色、敌人、地表、环境、VFX、UI 与音频资源的保留/重做清单。
- 黄金 90 秒镜头脚本和真实输入录制脚本说明。

退出门：四张目标帧在同一视觉语言下成立，HUD 占用、世界可见区域和主要操作提示位置已经确定，
再进入场景和代码改造。

### R9-1：角色、敌人和世界首屏

工作：

- 校正主角与 NPC 的默认 idle 剪影、脚底、武器持握和动画切换；截图等待稳定姿态后再取帧。
- 检查 run/attack/cast/hit/death 的预备、命中和恢复段，避免动作状态切换回绑定姿势。
- 让第一批食炁兽和 Boss 在体型、晶簇、头部、步态与敌意色上具有独立剪影。
- 为阵灯隘口入口建立道路边缘、地表变化、前中后景环境节奏和自然边界，隐藏裸露清屏色。
- 统一标题肖像、地图角色和菜单角色信息中的主角形象。
- 调整环境光、主光、阴影距离和功能灯光，使角色、道路、互动对象与前摇同时可读。

退出门：标题、入口探索、互动和首战截图均无绑定姿势、大片无节奏纯色地面或明显裸露黑边；关闭
HUD 后仍能从世界构图识别道路、玩家、守灯人、敌群和危险方向。

### R9-2：共享 UI 系统与核心界面

工作：

- 建立本作共享 Theme Resource，统一标题、正文、辅助文字、按钮、列表、滑块、焦点和禁用状态。
- 标题页移除技术演示口吻，保留开始、读取、设置和桌面退出所需的清晰层级。
- 探索 HUD 默认只保留必要目标；互动提示与出口标签执行避让，同一信息不在世界和 HUD 重复显示。
- 战斗 HUD 保留体力、真气、目标和六个动作，但以图形、状态遮罩和设备键位建立主次；移除常驻的
  Shift/Ctrl/Tab 整行教程。
- 对话继续使用逐字、补全/推进和语义选项，但统一姓名签、正文、等待标记和焦点语言。
- 菜单、商店、存读档和设置接入共享主题；设置拆分为显示与音频、操作、辅助功能等清晰分类，
  不把全部配置压在同一平面。
- 存读档优先使用现有地图、角色、境界、金钱等摘要，不为界面装饰扩张存档 schema。

退出门：标题、HUD、对话、菜单、设置和存读档并排检查时可被识别为同一产品；键鼠和手柄焦点
完整，没有文字越界、提示重叠或依赖颜色单独传达的关键状态。

### R9-3：默认操作、引导与动态手感

工作：

- `Esc` 在地图中打开暂停菜单，在模态界面中返回；`M` 可以保留为次要快捷键，手柄 Start 保持一致。
- F5/F6/F9 等调试或快速存读档入口只在开发构建出现，不进入正式玩家引导。
- 高级的 Shift 原地攻击、Ctrl 强制移动和 Tab/R3 切换目标通过首次情境提示或操作页说明，不常驻 HUD。
- 点地、不可达、点敌、互动、追击中断和资源不足使用互不混淆的世界反馈与短 HUD 原因。
- 校正点击到起步、WASD 接管、追击停止距离、攻击缓冲、闪避响应、目标保持和镜头偏置的动态节奏。
- 重绑界面检查冲突、清除、恢复默认和键鼠/手柄切换；最近输入设备提示在真实混合输入中稳定。
- 保留减少闪烁与命中停顿模式，并验证它不删除前摇、火花、剑弧、声音和资源变化。

退出门：键鼠和手柄各自完整跑通黄金 90 秒；暂停、失焦、对话、设置和返回地图后没有输入残留；
录像中不存在可见的静默拒绝、目标跳变或镜头突跳。

### R9-4：推广与回归

工作：

- 黄金 90 秒通过后，再把共享主题、角色姿态、HUD 规则、环境边界和操作契约推广到其余四张地图。
- G6、G4、R7 与 UI 截图继续验证内容状态和功能分支，并增加独立的 R9 成品表现截图集。
- 更新 README、requirements、architecture、asset pipeline、visual acceptance 和 roadmap 中实际发生的
  公共输入、素材、界面与验收变化。
- 完整运行内容校验、地图生成校验、自动测试、真实 Metal 截图和动态体验检查。

退出门：五张地图和所有顶层界面没有旧主题或旧操作提示残留；既有剧情、战斗、地图生成和 v6
存档回归全部通过。

2026-08-20 实施记录：

- 五张地图统一实例化游戏层 `roadside_map_hud_3d.tscn`，由它向通用 Framework HUD 注入共享
  Theme 与六个动作 SVG；Framework 不反向依赖 `game/` 或原创素材目录。
- 北坡原野、药草地、小铺和北坡兽径补齐复用入口环境、路灯、山脊和边界节奏，并统一收敛环境光；
  任务卡直接显示各自 StoryModule 的当前目标，无目标时隐藏。
- 标题、HUD、对话、菜单、商店、设置和存读档均使用共享主题；空行囊具有明确空状态和可见默认焦点。
- 内容校验、全量测试、三张地图固定 seed 校验，以及 G6/G4/R7/UI/R9 五组 Metal 截图全部通过。
- `capture_r9_dynamic_diagnostic.gd` 的四种 60 FPS 自动诊断通过；闪避残影不再复制角色运行时轮廓
  material chain，命中停顿使用 WeakRef 跳过已释放的战斗 View，Metal Compatibility 退出时无空材质
  依赖或失效实例告警。完整记录见
  `docs/baselines/r9/automated-dynamic-diagnostics.md`。
- 逐项审计发现三类角色的动画名匹配从未成功；现改用 Godot 路径文件名语义匹配，并由非静态关键帧、
  relaxed idle 与 AnimationPlayer 当前动画测试覆盖。五套截图和四段自动诊断均已在修复后重生成。
- 真人执行包提供 `--r9-field-test-profile` 隔离默认设置/存档、`--r9-field-test-log` 记录真实原始输入，
  以及 `field-test-results.template.json`、汇总模板和 `r9_field_test_cli.gd`。CLI 会拒绝缺录像、缺日志、
  覆盖项不足、设备分布不足、未达 `4/5` 或存在任一严重故障的结果，但不能替代人工观察。

## 7. 验收证据

### 7.1 自动门

继续运行仓库现有工程、内容、地图生成和测试命令。R9 新增或修改的规则至少覆盖：

- `Esc/M/Start` 的地图打开、界面返回和输入隔离。
- HUD 探索/战斗/模态状态切换以及键鼠/手柄提示互斥。
- 互动提示与出口提示不会同时占用同一屏幕区域。
- 动画状态切换不会在正常 idle/run/attack/cast/hit/death 路径停留于绑定姿势。
- 设置分类、重绑冲突、清除/恢复默认和辅助模式持久化。
- 黄金流程结束、暂停和切图后没有导航、攻击、目标或透明材质残留。

### 7.2 静态门

R9 实现时新增一个确定性 Metal 截图工具，输出 `/tmp/godot-pal-r9/`：

1. 标题首次焦点。
2. 阵灯隘口入口探索。
3. 点地落点与道路。
4. 守灯人互动提示。
5. 键鼠首战 HUD。
6. 手柄首战 HUD。
7. 敌人前摇与玩家命中帧。
8. Boss 冲撞构图。
9. 对话正文与选项。
10. 暂停菜单。
11. 设置分类与重绑。
12. 存读档槽摘要。

十二张图都必须在 `640 x 360` 下检查世界主体、角色姿态、文字层级、焦点、遮挡、功能色和设备提示。
G6/G4/R7/UI 旧截图继续作为功能回归集，但不能单独作为 R9 成熟度通过证据。

### 7.3 动态门

使用真实 Metal 运行时录制至少四段 60 FPS 画面：

- 完整黄金 90 秒。
- 连续点地、不可达、WASD 接管、点敌追击和取消。
- 普攻、三个技能、闪避、资源不足、受击、Victory 与 Defeat。
- 键鼠/手柄切换、暂停、设置、重绑、对话与返回地图。

逐帧检查输入到反馈的延迟、动画衔接、相机平滑、命中停顿、遮挡淡出和 UI 状态切换。静态截图无法
代替此门。

### 7.4 首次玩家盲测门

至少邀请 5 名未阅读 README、未参与实现的玩家，分别覆盖键鼠和手柄。不给操作说明，只记录行为、
误解和求助点。通过条件：

- 至少 4/5 能从标题开始游戏，并在 30 秒内主动移动。
- 至少 4/5 能在 90 秒内理解守灯人或世界目标的互动方式。
- 至少 4/5 能在首次战斗中完成普攻、一次技能和一次闪避，并说出体力与真气的区别。
- 至少 4/5 能独立打开菜单、找到设置并返回游戏。
- 5/5 的流程中不出现输入锁死、剧情并发、无法返回、不可见关键前摇或必须重启的问题。

盲测未通过时，先修正反馈、布局或默认操作，再讨论增加教程文字。

## 8. 优先级

P0：黄金 90 秒、角色稳定姿态、隘口入口画面、共享主题、战斗 HUD 信息减负、互动提示避让、
`Esc` 暂停/返回和动态录制。

P1：菜单/商店/存读档/设置统一、其余地图推广、重绑冲突、首次情境提示、完整 R9 截图集和盲测。

P2：盲测证明确有价值后再考虑更丰富的过渡、额外环境动画、手柄震动或非关键装饰；这些不能阻塞
P0/P1 的可读性和操作完成。

## 9. 完成定义

R9 只有在自动门、十二张静态图、四组动态录像和首次玩家盲测全部通过后才能标记完成。完成表示
当前纵向切片具备可对外展示和继续扩展内容的表现/操作基线，不表示内容量已经达到商业发行规模。
R9 完成前，不进入新境界或新地图的内容决策门。
