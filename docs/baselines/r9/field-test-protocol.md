## 1. 运行准备

- 使用 Godot 4.8、Metal Compatibility、`1280 x 720` 的默认 2 倍窗口与 60 FPS 录制。
- 不删除测试者已有存档或设置；每次运行使用下述全新隔离 profile，保留默认键位与中文界面。
- 从标题页开始，不使用截图工具、调试存读档或脚本注入输入。
- 录像存入 `/tmp/godot-pal-r9-dynamic/`，记录 Godot revision、设备和输入设备型号。
- 每段录像同时保留系统输入显示或独立按键日志，便于区分输入延迟与玩家停顿。

复制 `field-test-results.template.json` 为 `field-test-results.json`，复制
`field-test-results.template.md` 为 `field-test-results.md`。不要修改模板本身，也不要预先把待执行项
填写成通过。

### 1.1 独立真实输入日志

调试构建支持显式、只记录不注入的 JSONL 输入日志，以及不会读取玩家现有设置/存档的隔离 profile。
每段录像使用两个独立且不存在的新路径启动：

```sh
godot --path . -- --r9-field-test-profile=/tmp/godot-pal-r9-field-test/profiles/01_golden_90s --r9-field-test-log=/tmp/godot-pal-r9-field-test/01_golden_90s.inputs.jsonl
```

其余三段按模板文件名替换路径。profile 路径已存在或日志文件已存在时启动会失败，防止复用旧状态或
覆盖证据；需要重录时移动旧目录并换一个全新路径。记录器保存 session 起止、Godot revision、实际
窗口/Viewport、渲染器，以及原始键盘、鼠标、手柄事件和匹配的 InputMap action。两个参数只在调试
构建生效，不改变 GameRun、场景流程或战斗结果。录像仍由系统录屏完成，不能使用 Movie Writer
固定步输出冒充真人实时输入。

## 2. 四段动态录像

### A. `01_golden_90s.mp4`

从标题首次焦点开始，依次开始游戏、移动到守灯人、互动、进入首战、完成普攻/技能/闪避，战后
打开菜单、进入设置并返回地图。保持正常生命周期，不跳 stage、不直接调用场景私有方法。

### B. `02_pointer_and_direct_control.mp4`

连续覆盖有效点地、不可达点、拖动改点、WASD 接管、点敌追击、松开取消、Ctrl 强制移动和
Shift 原地攻击。逐帧记录输入到落点/拒绝反馈、玩家起步和追击停止的间隔。

### C. `03_combat_feedback.mp4`

覆盖普攻、三个技能、闪避、真气不足、冷却拒绝、受击、Victory 与 Defeat。检查前摇、剑弧、
火花、资源变化、命中停顿、死亡恢复和减少闪烁模式；辅助模式不能删除危险方向和资源反馈。

### D. `04_device_modal_roundtrip.mp4`

在同一运行中切换键鼠与手柄，使用 Esc/M/Start 打开菜单，进入设置，实际完成一次无冲突重绑、
一次冲突尝试和恢复默认，再进入对话与存读档并返回地图。检查焦点、提示设备与输入残留。

每段逐帧复核结果记录为 `通过 / 缺陷 ID / 时间码 / 观察`；任何输入锁死、无法返回、绑定姿势、
关键前摇不可见或状态残留均直接判失败。

## 3. 首次玩家盲测

招募至少 5 名未阅读 README、未参与实现的玩家，键鼠与手柄都至少覆盖 2 人。观察者只说
“请从标题开始玩”，不讲键位、目标或战斗规则，也不代替玩家操作。

每名玩家记录：

| 字段 | 内容 |
|---|---|
| 参与者 | 匿名编号 P1–P5 |
| 设备 | 键鼠 / 手柄与型号 |
| 首次移动 | 从标题开始计时；是否在 30 秒内 |
| 首次互动 | 行为路径、误解、求助；是否在 90 秒内理解 |
| 首战 | 是否完成普攻、技能、闪避；如何描述体力与真气 |
| 菜单往返 | 是否独立找到设置并返回 |
| 严重故障 | 锁死、并发、无法返回、前摇不可见、重启 |
| 原话 | 只记观察与玩家原话，不替玩家解释 |

通过条件沿用 R9 计划：前四项至少 4/5 成功，严重故障必须 5/5 为零。失败项先转成可复现缺陷，
优先修正默认操作、反馈和布局；不能用测试后的口头教学把失败改记为通过。

## 4. 结果归档

完成后在本目录新增 `field-test-results.md`，写明日期、build commit、设备分布、四段录像路径、
逐项计数、缺陷链接与是否通过。只有录像和 5 人原始记录都存在时，才能把 R9 标记完成。

同时填写 `field-test-results.json` 并运行只读完整性校验：

```sh
godot --headless --path . -s res://tools/r9_field_test_cli.gd -- validate res://docs/baselines/r9/field-test-results.json
```

校验器检查四个指定 MP4 与对应真实输入 JSONL、60 FPS/1280×720 记录、逐项覆盖、Godot revision、
五名参与者、键鼠/手柄各至少两人、四项 `4/5` 门槛和 `5/5` 无严重故障。它只能拒绝不完整证据，
不能替代人工逐帧复核或证明填写内容真实。
